## Findings

1. **Medium. A placeholder address in a label hides a real address behind it.**
   `skills/draw/scripts/src/scan-secrets.mjs:129-130`: `value.match(p.re)` takes the first
   address only, and when it is a placeholder the pattern is skipped for the whole string.
   Repro: a label "Gửi user@example.org và <real address at congty.vn>"
   (`r5/a5/two.ir.json`), `CLI emit --to figjam`: exit 0, 0 warnings, text written. The
   same real address alone is refused for figjam. The exemption of 2.0.5 made this path.
2. **Low. The FigJam refusal for a telephone number suggests the mail placeholder.**
   `skills/draw/scripts/src/pipeline.mjs:40`: the hint for `personal-data` is fixed to
   `(<customer e-mail>)`. Repro: `CLI emit --to figjam r5/a5/phone.ir.json`: the message
   says `<customer phone>`, the hint says `<customer e-mail>`. This is the failing point of
   A5.
3. **Low. Only the first cut slug is named.** `skills/draw/scripts/src/emit-mermaid.mjs:64`
   uses `find`, so `valid-ref-parts.json`, which has two refs longer than 16 characters,
   gets a warning for `order-sync-02-store` only, while `r5/a4/fx.png` shows both cut
   ("order-sync-02-st / ore" and "order-sync-01-lo / ad"). A user who shortens the named
   slug gets the next warning on the next emit. In a bundle the same message still says
   "in this single file" (`r5/a4/run-one`).
4. **Low. The scan exempts more than the closing contract lists.**
   `scan-secrets.mjs:58` also passes an address under `.localhost` and one that begins
   `xxx@` at any domain; `closing-contract.md:104-107` names neither. Repro:
   `r5/a5/lh.ir.json` and `r5/a5/xxx.ir.json` pass figjam with 0 warnings. Related, as
   information: the message of a secret guess still quotes four characters
   (`toke…(15 chars)`, `r5/i18/guess.ir.json`); for a mail address or telephone number
   nothing is quoted, as 2.0.5 intends.
5. **Low, open since round 4. In the flowchart fallback one connection is drawn through a
   node.** In `r5/i30/arch.png` the connection from the API to "SQS orders" passes through
   "Worker giao hàng". This is Mermaid's routing of `r5/i30/arch.mmd`; the CLI prints no
   warning for it.
6. **Info, open since round 4. A reported wrap lies on a connection.** In
   `r5/i37/aws.ja.png` (crop `r5/i37/crop-api.png`) the SQL connection starts inside the
   second line of the API's name ("Fargate）"). The wrap is reported and
   `variants.md:126-132` describes the outcome.

Also observed, no verdict attached: `--allow-sensitive` lets a `password=<value>` label
through on drawio (exit 0, file written, one warning), while `closing-contract.md:96-98`
says "no target writes it". The refusal's own hint offers the flag, so this reads as
intended, but the two texts do not say the same thing. `docs/install.md` orders its
sections 2.0.0, 2.0.1, 2.0.2, 2.0.5, 2.0.4, 2.0.3.
